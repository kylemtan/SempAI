# SempAI

AI-powered meal planning web app. Generate a personalised weekly meal plan, browse full recipes sourced from real cooking sites, manage your shopping list, and add items directly to your Kroger cart.

## Features

- **AI meal planning** — generate 1–7 days of meals starting on any date, with full recipe details (ingredients, steps, macros, source links)
- **Two recipe generation modes** — **Web Search** (default) plans recipes with Claude, finds the real recipe on a cooking site via Tavily, and writes the final recipe from that real content; **AI Generated** skips the web entirely and has Claude write the recipe from its own training knowledge in one step. Toggle in the sidebar's "Recipe Search" section
- **Customisable preferences** — cuisine, dietary lifestyle (vegan, halal, kosher…), allergens, macro targets, prep/cook time limits, and meals per day (1–6)
- **Ingredient use-up** — tell SempAI what's in your fridge and it'll work those ingredients into 1–2 recipes
- **Selective regeneration** — swap out individual meals without regenerating the whole plan
- **Favorites & pinning** — star recipes to save them; pin favorites so they appear in your next generated plan
- **Recent recipes** — automatically avoids repeating recipes for 4 weeks
- **Shopping list** — combined ingredient list with quantity estimates and a running total price. Merging is smarter than an exact-text match: plural/singular variants ("Shallot"/"Shallots"), hyphenation differences, quality qualifiers ("extra virgin olive oil" vs. "olive oil"), and recipe-speak/retail-speak synonyms (scallion/green onion) all collapse into one row — the more descriptive wording wins for display
- **Smart Kroger product matching** — connect your Kroger account and SempAI automatically picks a real product per ingredient, filtering out non-food and wrong-department matches, translating recipe-speak to retail-speak, and multiplying quantities to cover what the recipes actually need. An Accurate/Balanced/Cheapest toggle controls how hard it shops for a lower price; uncertain picks are flagged ⚠ Verify for a quick manual check
- **Claude-assisted shopping matching** *(Full Access only)* — ask Claude to double-check flagged items (with recipe/cuisine context, so it knows "Thai chili" needs an actual Thai variety) or let it pick every product directly; it says so explicitly when no suitable match exists rather than forcing a bad substitute
- **Manual review mode** — step through your own chosen set of ingredients (just the flagged ones, everything, or a custom checkbox selection) one at a time, picking from the top handful of most-relevant candidates (ranked by SempAI's own scoring or Kroger's own order, with a "show all" escape hatch) — sortable by price or name too, and your sort preference persists across ingredients and future shopping trips
- **Pantry** — log what you already have; pantry items are separated in the shopping list and auto-added when you cart items, with color-coded categories and drag-and-drop to recategorize
- **Export** — save your plan as a PDF (schedule, shopping list, all recipes, or everything) or add meals to any calendar app via `.ics`
- **Guided tour** — a short, interactive first-visit walkthrough that spotlights the real controls (preferences, Generate, a meal card, Pantry, Favorites, Recent Recipes, Shopping List) in sequence; replay it anytime from the Help modal
- **Dark mode**

See the in-app **Help (?) → How it works** for a detailed walkthrough of both generation pipelines and the full shopping-match algorithm.

## How it works

### Recipe generation — two pipelines

**Web Search** (default): a three-step pipeline. (1) Claude plans which recipes fit your preferences and picks a plausible source site per recipe. (2) The backend searches the web via Tavily for that recipe, extracting the real ingredient list and instructions straight from the source page (preferring the page's embedded Schema.org recipe data, falling back to Tavily's content extraction). (3) Claude writes the final structured recipe (macros, steps, ingredients) using that real retrieved content, so it can't contradict the actual recipe. Each day of the plan is synthesized in parallel.

**AI Generated**: a single step. Claude writes the recipe entirely from its own training knowledge, with no web search at all. Faster, but not sourced from any real page — these recipes are marked "Generated by Claude" instead of a source link. Toggle between the two in the sidebar's "Recipe Search" section; it applies to both full-plan generation and selective regeneration.

### Shopping list — Kroger product matching algorithm

Clicking "Find Products" runs every ingredient through several layers before picking a product, in order:

1. **Non-food category exclusion** — products from categories like candy/gum, personal care, household, pet, or automotive are dropped outright, even on a strong text match (searching "mint leaves" won't return breath mints).
2. **Recipe-speak ↔ retail-speak aliasing** — a table of known naming differences (scallion↔green onion, cilantro↔coriander, garbanzo↔chickpea, and more) is applied to both the search query and the scoring, so a differently-worded product still counts as a real match.
3. **Full word-coverage scoring** — a candidate only counts as a strong match if *every* meaningful word in the ingredient appears in its description, not just one shared word ("toasted rice powder" needs more than a product that merely contains "rice").
4. **Phrase adjacency** — among candidates tied on word coverage, ones where the words appear together as an actual phrase are preferred over the same words appearing scattered incidentally.
5. **Department plausibility** — candidates from actual cooking-ingredient departments (produce, meat, dairy, spices, condiments, grains, baking, international, etc.) are preferred over technically-matching products from snacks, beverages, or candy that just happen to share a flavor name (a "Thai chili" search won't settle for hot-sauce-flavored chips).
6. **Quantity matching** — if a recipe needs 6 onions and the product comes in a 3-count bag, 2 are added to the cart, not 1; this only kicks in when the unit is unambiguous (a "can," "jar," or explicit pack count on the label), never guessing on ambiguous units like "cloves" or "slices."
7. **Remembered corrections** — manually picking a different product for an ingredient is remembered (per browser) so future shopping lists use it automatically; explicitly removing a pick without a replacement excludes that product from future auto-picks for that ingredient.

An **Accurate / Balanced / Cheapest** toggle (next to "Find Products") controls how many of the already-vetted candidates get price-compared — Accurate trusts Kroger's own top-ranked match, Cheapest shops across more of them for a lower price. Widening this never reopens the door to a wrong-category or wrong-form product; it only decides which of several *already-valid* options wins on price. Picks the algorithm isn't fully confident about are flagged **⚠ Verify** and sorted to the top of the list.

### Claude-assisted shopping matching (Full Access only)

Two opt-in features hand ingredient matching to Claude directly instead of (or on top of) the algorithm above:

- **Ask Claude to Verify** — sends just the ⚠ Verify-flagged items (or everything, via a checkbox) to Claude in a single batched request, along with which recipe(s) each ingredient is used in and their cuisine — so it can tell, e.g., that "Thai chili" needs an actual Thai variety rather than any hot pepper, or that a specialty ingredient genuinely isn't something a US grocery store carries.
- **Let Claude pick directly** — skips the algorithm entirely; Claude picks (or explicitly declines to pick) every ingredient from the start. Remembered corrections and exclusions still apply first. If Claude's request fails (e.g. rate limited), it falls back to the algorithm automatically rather than leaving the list empty.

Either way, if none of the candidates are a genuine match, Claude says so explicitly ("no suitable match") instead of forcing a substitute — you can then search Kroger's site directly or pick manually from the same candidates it saw. Both features use Claude Sonnet 5 in a single batched call regardless of list size, and require **Full Access** (see below); without it, the controls are still visible but locked, with a short explainer on click.

### Manual review mode (available to everyone, no Full Access required)

From "Review Cart," click **Manually Review Items** to pick your own scope — just the ⚠ Verify-flagged items, everything, or a custom checkbox selection — then step through them one at a time with Back/Next. Each ingredient shows only its top few candidates (capped at 6 by default, with a "show all" link if the right one isn't there), sorted by SempAI's own relevance scoring by default. Switch to Kroger's own order, price, or name instead — the sort choice is remembered across ingredients and future shopping trips. Picking a product manually here is treated the same as any other manual correction: it's remembered for next time.

### Full Access & Demo Mode

By default the app runs in **Demo Mode**: 2 AI meal-plan generations per day, and the two Claude-assisted shopping features above are locked (the automatic matching algorithm still works fully). Visiting the app via a **Full Access** link — `https://yourapp.com/<code>` or `?access=<code>`, using the `FULL_ACCESS_CODE` you set — silently grants a long-lived signed cookie that raises the limit to 10/day and unlocks the Claude shopping features. Current mode is shown as a badge in the top-right of the page.

## Local development

### Prerequisites

- Node.js 20+
- API keys for [Anthropic](https://console.anthropic.com), [Tavily](https://tavily.com), and optionally [Kroger](https://developer.kroger.com)

### Setup

```bash
git clone https://github.com/kylemtan/SempAI.git
cd SempAI
npm install
```

Copy the environment file and fill in your keys:

```bash
cp backend/.env.example backend/.env
```

```env
ANTHROPIC_API_KEY=...
TAVILY_API_KEY=...
KROGER_CLIENT_ID=...       # optional
KROGER_CLIENT_SECRET=...   # optional
PORT=3001
```

Start both servers:

```bash
npm run dev
```

The app runs at `http://localhost:5173`. The Vite dev server proxies `/api` and `/auth` to the Express backend on port 3001.

## Deployment (Render)

The repo includes a `render.yaml` that configures everything automatically.

1. Push to GitHub
2. Go to [render.com](https://render.com) → **New → Blueprint** and connect this repo — Render will pick up `render.yaml`
3. Set the following environment variables in the Render dashboard:

| Variable | Description |
|---|---|
| `ANTHROPIC_API_KEY` | Anthropic API key |
| `TAVILY_API_KEY` | Tavily API key |
| `KROGER_CLIENT_ID` | Kroger app client ID |
| `KROGER_CLIENT_SECRET` | Kroger app client secret |
| `APP_URL` | Your Render public URL, e.g. `https://sempai.onrender.com` |

4. In the [Kroger Developer Portal](https://developer.kroger.com), add `https://your-app.onrender.com/auth/kroger/callback` as an allowed redirect URI.

In production, Express serves the built frontend as static files — no separate static site needed.
